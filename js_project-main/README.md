# 등교 체크인 · 내 클래스

Supabase 인증과 학급 데이터를 사용하는 Vite 프로젝트입니다. 학급을 만든 계정은 관리자 화면, 학급코드로 입장한 계정은 학생 화면을 사용합니다.

## 실행과 DB 연결

```sh
npm ci
npm run dev
```

`.env.example`을 참고해 `.env`에 Supabase 공개 키와 카카오 지도 키를 설정합니다. 인증 설정은 [AUTH_SETUP.md](AUTH_SETUP.md), 학급 생성·입장·멤버 관리는 [MEMBERS_SETUP.md](MEMBERS_SETUP.md)를 참고하세요.

사진으로 등교 인증은 [PHOTO_CHECKIN_SETUP.md](PHOTO_CHECKIN_SETUP.md)에 따라 DB 마이그레이션, 서버의 `OPENAI_API_KEY` 설정, `photo-checkin` 함수 배포를 완료해야 합니다. 학생의 등교 버튼은 학교 위치 확인 후 촬영 화면으로 연결됩니다. 서버가 제시어와 사진의 일치를 확인하고 출석을 저장한 경우에만 완료됩니다.

학급 관련 기존 마이그레이션 4개를 적용한 뒤 Supabase SQL Editor에서 [학사일정 마이그레이션](supabase/migrations/202611010001_academic_calendar.sql)을 실행하세요. 기존 `custom_calendar_events` 데이터는 유지하며, 종료일 없는 기존 일정은 하루 일정으로 처리합니다. 학생 조회 권한과 관리자 등록·삭제 권한을 추가하므로 기존에 일정 테이블이 있어도 적용해야 합니다. 이어서 [일정 수정 마이그레이션](supabase/migrations/202611010002_edit_academic_calendar.sql)을 실행하면 관리자 수정 권한이 적용됩니다. 이미 첫 번째 학사일정 마이그레이션을 적용했다면 수정 마이그레이션만 추가로 실행합니다.

## 학사일정

- 관리자: `+ 일정 추가` 또는 빈 날짜 우클릭 → 일정명·시작일·종료일·설명 입력 → 등록. 등록된 일정이나 날짜를 우클릭하면 수정·삭제 메뉴가 표시됩니다. 여러 일정이 겹친 날짜는 일정별 메뉴를 제공합니다.
- 관리자 달력의 날짜·일정에 마우스를 올리거나 키보드로 포커스하면 이름·기간·설명 팝업을 표시합니다. 날짜를 선택해도 달력의 칸 크기는 바뀌지 않습니다. 모바일에서는 일정을 눌러 상세 내용을 확인할 수 있습니다.
- 학생: 공지사항과 같은 테두리 카드 안에서 가입한 학급의 등록 일정, 기간, 설명과 크게 표시된 `D-N`을 확인합니다. 일정이 없는 경우에도 카드와 안내 문구는 유지합니다. 시작일은 `D-DAY`, 여러 날 일정의 기간 중에는 `진행 중`을 표시합니다. 날짜는 한국 시간 기준입니다.
- 학생 목록에는 예정·진행 중인 일정만 표시합니다. 새로고침 버튼, 일정 개수, 상태 필터, 지난 일정 선택, `MY CLASSROOM` 문구는 표시하지 않습니다.
- 학생 화면은 열려 있는 동안 30초마다, 화면에 다시 돌아올 때 DB를 조회합니다. 관리자의 등록·수정·삭제가 다음 조회에 반영됩니다.
- 관리자 달력의 일정 막대는 위에서 아래로 더 진한 파란색을 사용합니다. 일요일과 공휴일 날짜는 빨간색, 토요일은 파란색이며 토요일과 공휴일이 겹치면 빨간색을 우선합니다.
- 공휴일은 나이스 학사일정의 공휴일 구분을 사용합니다. 기존 `neis-calendar` 배포가 구분 값을 반환하지 않으면 공휴일 일정명으로 판별합니다. 서버의 구분 값을 사용하려면 수정된 `supabase/functions/neis-calendar/index.js`도 배포합니다. 방학·재량휴업일은 공휴일로 취급하지 않습니다.
- 관리자 달력의 기존 나이스 조회는 유지합니다. 학생에게 공유하는 대상은 관리자가 직접 등록한 일정입니다. 나이스 연결이 실패해도 직접 등록 일정은 표시합니다.
- 같은 학급의 학생만 조회할 수 있고, 등록·수정·삭제는 학급 소유자만 가능합니다. 수정은 일정명·설명·기간만 변경할 수 있고 소속 학급과 작성자는 바꿀 수 없습니다. 탈퇴·멤버 제외·학급 삭제 후에는 DB에서 일정 접근을 차단합니다.
- 선택한 날짜는 기존의 연한 파란색을 유지하고, 일정 막대를 더 진한 파란색으로 표시해 구분합니다. 겹치는 일정은 아래 막대일수록 더 진하게 표시합니다.

## 등교시간 설정

사진 인증 마이그레이션까지 적용한 뒤 [등교시간 마이그레이션](supabase/migrations/202611020001_attendance_deadline.sql)을 적용합니다. 기존 학급의 등교시간은 관리자가 저장하기 전까지 미설정 상태입니다.

관리자 **내 클래스 → 학급 카드 오른쪽 점 세 개 → 등교시간 설정**에서 마감 기준과 시·분을 필수로 입력합니다. 초 단위를 선택하면 초도 필수입니다. 필수 항목에 `*`를 표시하며, 설정 창 뒤에는 기존 일정 추가 창과 같은 블러 배경을 적용합니다. 입력한 기준의 정상 등교·지각 경계를 미리 보여 줍니다.

| 마감 기준 | 08:00 설정 시 정상 등교 | 지각 시작 |
| --- | --- | --- |
| 분 단위 | 08:00:59까지 | 08:01:00부터 |
| 초 단위, 초를 00으로 입력 | 08:00:00까지 | 08:00:01부터 |

시간은 매일 한국 시간 기준입니다. 사진 인증 요청을 DB가 접수한 서버 시각을 초 단위로 비교하며, AI 응답 대기 시간은 포함하지 않습니다. 불일치 후 재촬영하면 새 사진의 제출 시각을 사용합니다. 설정 변경은 다음 사진 제출부터 적용되며, 이미 제출한 사진과 과거 출석에는 소급 적용하지 않습니다. 출석 완료 시 학생 화면과 카메라 화면에 지각 여부를 표시합니다.

설정은 해당 학급의 소유자만 저장할 수 있습니다. 학생과 다른 학급의 관리자는 설정을 수정할 수 없고, 정상·지각 판정도 브라우저가 아닌 DB에서 저장합니다. 원래 등교시간을 설정하지 않았던 과거 출석에는 정상·지각 분류를 추가하지 않습니다.

## 코드 구조

- 루트 `*.html`: 화면 구조, 모달, 반복 항목의 `<template>`.
- `src/css/`: 페이지 스타일. 관리자 사이드바는 `main.css`, 달력·일정 폼은 `admin.css`를 사용합니다.
- `src/js/admin.js`: 관리자 계정·학급·멤버 관리. `admin-calendar.js`는 관리자 달력 동작을 담당합니다.
- `src/js/student.js`: 학생 학급 입장·탈퇴·사진 인증 시작·출석 상태·일정 화면.
- `src/js/classroom-camera.js`: 서버 제시어·촬영·재촬영·판정 결과 화면. `checkin/camera-session.js`는 카메라만, `checkin/client.js`는 위치·인증 요청만 담당합니다.
- `supabase/functions/photo-checkin/`: 서버 사진 인증 진입점. 실제 판정 로직과 공통 제시어는 인접한 `_shared/`에 있습니다.
- `src/js/calendar.js`: 관리자·학생 공통 일정 조회·저장·수정·삭제와 날짜/D-day 계산.
- `src/js/classroom-store.js`: 기존 학급 데이터와 RPC 접근.

JS는 HTML 템플릿을 복제하고 데이터·이벤트를 연결합니다. HTML 문자열 삽입과 스타일시트 주입은 사용하지 않습니다. 팝업 좌표만 JS에서 계산해 CSS 변수로 전달합니다. 카카오 SDK의 스크립트는 설정 키로 URL을 구성해 동적으로 불러옵니다.

## 검증

```sh
npm test
npm run build
```

[일정 권한 SQL 테스트](supabase/tests/academic_calendar.sql)는 마이그레이션을 적용한 테스트 DB에서 실행할 수 있습니다. 관리자 저장·수정·삭제, 학생 읽기 전용 접근, 타 학급 차단, 탈퇴와 학급 삭제 후 접근 차단을 검증합니다. 테스트용 데이터와 정책은 마지막 `rollback`으로 되돌립니다.

[등교시간 SQL 테스트](supabase/tests/attendance_deadline.sql)는 관리자 권한, 시간 입력 검증, 초 단위 경계, 재촬영 시각, 설정 변경 전후의 판정 유지, 출석 결과의 저장·조회까지 검증합니다. 테스트 DB에서 실행하며 마지막 `rollback`으로 테스트 데이터를 되돌립니다.
